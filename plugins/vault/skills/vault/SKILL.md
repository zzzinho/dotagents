# vault — 지식 저장

Eugene Yan, "Working with AI" (https://eugeneyan.com/writing/working-with-ai/) 의 vault 방법론을 본 환경에 맞춘 것. `~/vault` 는 facts·project state·domain knowledge, `~/.claude/` 는 preferences·workflows — 이 스킬은 전자만 다룬다.

## 쓰기 경계

이 스킬로 파일을 쓰는 곳은 **`~/vault/` 안뿐**이다. `~/code/`, `~/.claude/` 등 외부 경로는 읽기만 한다. vault 문서의 백업·사본을 다른 곳(스크래치패드 포함)에 만들지 않는다. 문서를 지울 때도 다른 곳으로 옮기지 않고 지운다.

## 원칙

- **객관적 지식만** 보관한다. 의견·해석·권장·트레이드오프 평가는 쓰지 않는다. 1차 자료가 직접 그렇게 말하면 그 자료의 말로 인용한다.
- **근거는 항상** 문서에 남긴다. 근거를 적을 수 없는 문장은 종류(외부 사실·실측·결정)와 상관없이 쓰지 않는다.
- **동시 수정 금지** — vault 는 한 번에 한 작업자만 고친다 (아래 잠금).

## 잠금

모든 쓰기가 `index.md` 를 건드리므로 vault 전체를 하나의 잠금으로 막는다.

- 첫 쓰기 전에 획득: `cd ~/vault && (set -C; echo "<세션·작업 설명> $(TZ=Asia/Seoul date '+%F %T')" > .lock)`
- `file exists` 로 실패하면 `cat ~/vault/.lock` 의 점유자를 사용자에게 알리고 멈춘다. 오래된 잠금이라도 직접 지우지 않고 사용자 확인을 받는다.
- 작업이 끝나거나 중단되면 반드시 해제: `rm ~/vault/.lock`
- 잠금을 쥔 동안에도 vault 를 고치는 서브에이전트를 병렬로 띄우지 않는다.
- 기존 파일은 Edit 로 고친다. Write 전체 덮어쓰기는 새 파일에만 쓴다.

## 디렉터리

```
~/vault/
├── index.md    # 전체 문서 목록 — 경로·요약·검색어. 다른 에이전트가 필요할 때 찾아보는 용도
├── kb/         # 프로젝트 독립 일반 지식 (도구·기술·개념, 외부 자료 요약)
├── notes/      # 용도 미정 — 쓰지 않음
└── projects/<kebab-case-name>/   # 프로젝트별 사실·발견·결정
```

- 특정 프로젝트의 환경·상태·결정은 kb 에 절대 넣지 않는다.
- 일반 지식과 프로젝트 사례가 섞이면 **분리**: 일반 부분은 kb, 프로젝트 부분은 projects. 서로 `[[파일명]]` (확장자 없이) 으로 연결.
- 인덱스는 `~/vault/index.md` 하나뿐이다. 하위 디렉터리나 코드 레포에 인덱스를 만들지 않는다. 외부 자료도 별도 목록 없이 각 문서 출처에 적는다.

## 절차

1. **분류** — kb / projects(어느 프로젝트) / 분리 여부를 정한다. 기존 문서 갱신이 맞으면 새로 만들지 않는다 (`ls ~/vault/kb ~/vault/projects/*` 로 확인).
2. **제목** — 파일명과 H1 모두 내용을 대표하는 **10자 이내**. 파일명은 kebab-case. 애매하면 후보 2~3개를 사용자에게 묻는다.
3. **날짜** — `TZ=Asia/Seoul date +%F` 결과를 쓴다. 시간은 적지 않는다.
4. **링크 검증** — 넣을 URL 마다 실행:
   ```bash
   curl -sL --max-time 15 -w '\n%{http_code} %{url_effective}\n' <URL> \
     | grep -Eio 'http-equiv="refresh"[^>]*|^[0-9]{3} https?://[^ ]*$'
   ```
   - 200 이면 **`url_effective`(최종 URL)** 를 적는다.
   - `http-equiv="refresh"` 줄이 나오면 HTML 리다이렉트다 (curl 은 못 따라감). 그 `url=` 대상을 다시 검증하고 그 URL 을 적는다.
   - 403·405·타임아웃 등 봇 차단 의심이면 WebFetch 로 한 번 더 열어 본다.
   - 그래도 실패하면 문서에서 빼고, 어떤 URL 이 왜 빠졌는지 사용자에게 보고.
   - 인증 필요·사설 저장소처럼 원리적으로 못 여는 링크는 링크 옆에 그 사실을 표기.
   - 미검증 링크를 추측으로 적는 것은 금지.
5. **사실 검증** — 작성 전에 넣을 내용을 사실 단위로 쪼개고, 하나씩 근거를 확인한다. **확인된 사실만 문서에 쓴다.**

   | 종류 | 확인 방법 |
   |---|---|
   | 외부 사실 (동작·스펙·옵션·버전·수치) | 1차 문서(공식 문서·릴리즈 노트·스펙·소스 코드, 의견이면 저자 본인 글)를 WebFetch 로 열어 원문 인용을 받는다. 프롬프트: `다음 주장을 직접 뒷받침하는 문장을 원문 그대로 인용하라. 없거나 다르게 말하면 NOT FOUND 와 실제 내용을 답하라: <주장>` |
   | 실측 (명령 출력·로그·재현 결과) | 그 출력이 대화에 실제로 있어야 한다. 요약이나 기억뿐이면 다시 실행하거나 뺀다. 출처에 `실측: <무엇을 어디서 실행> (YYYY-MM-DD)` 로 적는다. |
   | 결정·계획 (projects 만) | 사용자가 대화에서 정한 것, 또는 레포에 반영된 것. 출처에 `사용자 결정 (YYYY-MM-DD 대화)` 또는 `근거: ~/code/<x>/<경로> (커밋 <hash>, YYYY-MM-DD)` 로 적는다. |

   - 다음은 문서에서 **뺀다**: NOT FOUND, 2차 자료(블로그·포럼·Q&A)로만 확인됨, 모델 지식·추론뿐, 문서끼리 내용이 엇갈림, 근거를 출처에 적을 수 없음.
   - 수치·옵션명·버전·명령은 인용한 원문 그대로 쓴다. 의역하면서 뜻을 넓히거나 좁히지 않는다.
   - 버전·시점에 따라 바뀌는 사실은 확인한 문서의 버전을 문장에 함께 적는다 (예: "Go 1.24 부터").
   - 해석·권장·트레이드오프·의견은 쓰지 않는다 (원칙 참고).
6. **작성** — 아래 형식. 같은 디렉터리 기존 문서의 스타일을 따른다.
7. **충돌** — 같은 파일명이 있으면 덮어쓰지 말고 이름 변경/병합을 사용자에게 묻는다.
8. **인덱스** — 문서를 추가·삭제하거나 내용이 바뀌면 같은 작업에서 `index.md` 의 해당 줄도 고친다 (형식은 아래). 끝나면 대조해서 출력이 없어야 한다:
   ```bash
   cd ~/vault && diff <(find kb projects -name '*.md' | sort) <(grep -oE '^- [^ ]+\.md' index.md | cut -c3- | sort)
   ```

기존 문서를 수정할 때도 그 문서의 기존 링크를 4번 방식으로 재검증하고 출처 첫 줄 날짜를 갱신한다. 죽은 링크는 보고한다. 새로 넣거나 바꾸는 문장은 5번 검증을 거친다.

## 문서 형식

```markdown
# <10자 이내 제목>

> YYYY-MM-DD

## 출처

전부 YYYY-MM-DD 접근 확인 (HTTP 200).

- <설명>: <최종 URL>
- 실측: <URL 없는 근거를 문장으로 — 대화 컨텍스트, 사용자 제공 로그, 직접 실행 결과 등>

## <본문 섹션들>
```

- `## 출처` 는 **모든 문서에 필수**, 예외 없음. URL 이 하나도 없으면 검증 날짜 줄은 생략하고 출처 문장만.
- 특정 주장의 근거 링크는 본문 그 자리에도 인라인으로 건다.
- 프런트매터 없음. 이모지 없음.
- 한국어로 정리. 결정적 문장은 원문 언어 그대로 인용.
- 본문 섹션은 내용에 맞게 자유롭게 (예: 핵심 개념 / 증상 / 원인 / 진단 / 해결 / 함정 / 트레이드오프). 날짜가 의미 있는 사실(실측·진단)은 섹션 제목이나 문장에 날짜를 남긴다.

## index.md 형식

```markdown
# vault index

## kb

- kb/<파일>.md — <요약 문장>. 검색어: <a>, <b>, <c>

## projects/<name>

- projects/<name>/<파일>.md — <요약 문장>. 검색어: ...
```

- 요약 문장: 문서가 **담고 있는 내용**을 한 문장으로. 순수 지식 정리면 무엇을 정리했는지, 진단·결정 기록이면 무엇을 기록했는지.
- 검색어: 5~10개. 본문에 실제로 나오는 고유명사 우선 — 도구·제품명, 에러 메시지·코드, 핵심 명령·옵션, 버전, 호스트명. 흔한 별칭은 함께 (예: k8s, kubernetes). 일반 명사는 넣지 않는다.
- 요약·검색어는 본문에서 옮긴 것이므로 별도 사실 검증 대상이 아니다. 본문에 없는 내용은 넣지 않는다.
- 그룹 순서: kb, 그 다음 projects 를 프로젝트명 순. 그룹 안은 파일명 순.
- index.md 는 문서 형식 규칙(10자 제목·날짜·출처)의 예외다.

## 마무리 보고

1. 생성·수정한 파일 경로
2. 링크 검증 결과 — 확인 개수, 제외한 URL 과 사유, 확인 불가로 표기만 한 URL
